Implementation plan // adopting brainstorm UI on top of shadcn + tailwind v4

tldr

Layer, don't replace. Your shadcn primitives (Button, Card, Input, Dialog, Sheet, etc.) stay exactly as they are. We add a thin Tally-flavoured layer on top: a few extra design tokens, a small set of composed components (LeaderboardRow, GameCard, SessionCard, PodiumCarousel, FAB, BottomNav), and a responsive shell.

The brainstorm proposes patterns, not a brand-new design system. Your tokens are already 80% of the way there — the primary colour is yellow, dark/light is wired, sidebar tokens exist. We just need a few semantic additions and a component library that uses them.

01 strategy in three bullets

  • Don't fork shadcn. Keep ui/button.tsx, ui/card.tsx, etc. untouched so future shadcn add upgrades keep working. Build new components in a sibling folder.
  • Extend tokens via CSS variables. Your :root + .dark blocks already define design tokens. Add a handful of semantic ones (--rank-gold, --rank-silver, --rank-bronze, --surface-elevated, --ring-strong). No JS, no theme provider rewrite.
  • Restyle only via promote. Don't reach into shadcn/ui/* and tweak it in place. If a primitive needs Tally-specific styling, graduate it (copy to components/, swap to --ds-* tokens, delete the shadcn import) — and only do that when (a) it's actually used in the app and (b) there's a clear, concrete reason the shadcn defaults don't fit. No speculative promotion.

02 namespace strategy: ds-*

Two parallel registries, never mixed:

  • shadcn tokens (--background, --primary, --accent, …) — left exactly as the CLI ships them. Used only by files inside src/shadcn/.
  • DS tokens (--ds-background, --ds-rank-gold, --ds-status-friend, …) — owned by you. Used by everything in src/components/.

Day-one trick: every --ds-* token starts as an alias of its shadcn counterpart. Zero visual change, full freedom to diverge later.

/* :root */
/* mirror — start identical, diverge over time */
--ds-background:        var(--background);
--ds-foreground:        var(--foreground);
--ds-card:              var(--card);
--ds-muted:             var(--muted);
--ds-muted-foreground:  var(--muted-foreground);
--ds-border:            var(--border);
--ds-primary:           var(--primary);
--ds-destructive:       var(--destructive);

/* purely DS — no shadcn equivalent */
--ds-rank-gold:         oklch(0.852 0.199 91.936);
--ds-rank-silver:       oklch(0.78 0 0);
--ds-rank-bronze:       oklch(0.62 0.13 50);
--ds-surface-elevated:  oklch(0.985 0 0);
--ds-surface-sunken:    oklch(0.96 0 0);
--ds-status-own:         var(--ds-primary);
--ds-status-friend:      oklch(0.7 0.13 230);
--ds-status-rented:      oklch(0.7 0.16 350);
--ds-success:            oklch(0.62 0.16 145);
--ds-warning:            oklch(0.78 0.17 75);

Then expose only the --ds-* family through @theme inline with a matching prefix:

--color-ds-background:        var(--ds-background);
--color-ds-rank-gold:         var(--ds-rank-gold);
--color-ds-status-friend:     var(--ds-status-friend);
/* … etc */

Now bg-ds-background, text-ds-rank-gold, border-ds-border all work in JSX. Anything not prefixed comes from shadcn — instantly readable.

What stays shadcn-only (don't namespace)

Mechanical scales aren't semantic to your product, so they don't benefit from a prefix. Keep these shared:

  • Radius scale (--radius, --radius-sm, --radius-md, …)
  • Animation durations / easings (when you add them)
  • Typography ramp if/when you add one

Only semantic tokens (colour, surface, status, rank, success/warning) get the --ds- prefix.

Component-graduation flow

  1. You run npx shadcn add button. File lands in src/shadcn/ui/button.tsx, drinks from --primary, --background, etc. Use as-is.
  2. You need a Tally-flavoured Button (extra fab variant, custom hover). Move file → src/components/button.tsx.
  3. While moving, swap tokens: every bg-primary → bg-ds-primary, every text-foreground → text-ds-foreground. This is the discipline that makes the namespace work.
  4. Update import paths in your app code from @/shadcn/ui/button → @/components/ui/button.
  5. If a future shadcn add dialog internally imports ./button, the CLI redownloads a fresh Button into src/shadcn/ui/. Your customized one is untouched.

Now bg-rank-gold, text-status-friend, bg-surface-elevated all work in JSX. No Tailwind config changes needed in v4.

Why semantic, not raw: calling it --rank-gold rather than --yellow-400 means dark mode, accessibility tweaks, and future rebrands all have one knob to turn. Same pattern as --primary / --destructive in shadcn.

3.1 typography

The brainstorm leans on a clear two-family split: a humanist sans for prose & UI, and a mono for labels, ranks, scores, and "data" moments (uppercase chip captions like PLAY TONIGHT, score lines, leaderboard numerals). Kalam in the brainstorm is wireframe chrome — do not ship it. The app's voice is Inter (or Geist if you'd rather) + JetBrains Mono.

/* fonts — load once in app/layout */
/* import { Inter, JetBrains_Mono } from "next/font/google" */

/* :root — same in light & dark */
--font-sans:    "Inter", ui-sans-serif, system-ui, sans-serif;
--font-mono:    "JetBrains Mono", ui-monospace, monospace;
--font-display: var(--font-sans);  /* display = sans, just heavier */
--font-hand:    "Kalam", cursive;       /* playful accent — sparingly */

/* type scale — tight, modular, mobile-first */
--text-xs:   0.75rem;   /* 12 — chip captions, table headers */
--text-sm:   0.875rem;  /* 14 — secondary copy, meta */
--text-base: 1rem;      /* 16 — body, list rows */
--text-lg:   1.125rem;  /* 18 — card titles */
--text-xl:   1.375rem;  /* 22 — section heads */
--text-2xl:  1.75rem;   /* 28 — page titles */
--text-3xl:  2.25rem;   /* 36 — hero scores, podium numerals */

/* expose to Tailwind */
@theme inline {
  --font-sans:    var(--font-sans);
  --font-mono:    var(--font-mono);
  --font-display: var(--font-display);
  --font-hand:    var(--font-hand);
}

Two tiny utility classes earn their keep. Add them once in globals.css:

/* eyebrow label — mono, uppercase, spaced */
.eyebrow { font: 600 var(--text-xs)/1 var(--font-mono); letter-spacing: 0.12em; text-transform: uppercase; color: var(--muted-foreground); }

/* numeric — always tabular, mono optional via --num-mono */
.num     { font-variant-numeric: tabular-nums; font-feature-settings: "tnum"; }
.num-mono{ font-family: var(--font-mono); font-variant-numeric: tabular-nums; }

/* hand accent — playful, slightly tilted, warm tone */
.hand    { font-family: var(--font-hand); font-weight: 700; transform: rotate(-1.5deg); display: inline-block; color: var(--primary); }

Why mono for labels & numbers: the brainstorm's "data feel" comes almost entirely from uppercase mono captions and tabular numerals — they signal this is information, not prose, and they keep columns aligned without manual width hacks. Using mono everywhere would feel like a terminal; using it only on labels + numerals gives you the analog-scoreboard vibe without the cosplay.

Don't: use Kalam for body copy, table cells, or anywhere it'd interrupt a reading rhythm; mix more than these three families; lean on it as personality (it's seasoning, not the dish); set sizes outside the scale.

05 guardrails (so shadcn stays clean)

  • Never edit files in components/ui/. If you need a variant of Button, add it via buttonVariants() extension in a sibling file, not by mutating the source.
  • One token registry. If you find yourself writing a hex inline, stop and add a token instead. The brainstorm explicitly avoids hex sprawl.
  • Don't add a second color framework. No tailwind.config.js color extensions in v4 — go through @theme inline only.
  • Mobile-first className order. Default = phone, md: = desktop. Matches the brainstorm direction (mobile is the real venue).

Watch out: your current --accent in dark mode is oklch(0.269 0 0) — a near-black grey, not yellow. shadcn uses --accent as a hover/highlight surface, distinct from --primary. Don't repurpose it for the brand yellow or you'll break every shadcn hover state. Use --primary for brand accents.

06 dark & light mode

You already have .dark wired with full token pairs and a Theme picker in Settings (System / Light / Dark). Treat that as the contract — every new pattern below has to look right in both. Most of the work is making sure each new token, ring, and shadow is defined in both blocks.

Switching mechanism (keep what you have)

  • Toggle document.documentElement.classList.toggle('dark', isDark). No theme provider, no React context for the value itself.
  • System mode = listen to matchMedia('(prefers-color-scheme: dark)') and apply on change. Persist the user's explicit pick (light / dark / system) in localStorage.
  • Apply the class before first paint (small inline script in <head>) to avoid a flash. shadcn docs cover the snippet.

Token pairing — every new token defined in both modes

The rule: if a token only appears in one block, it's a bug. Use this as a quick checklist:

Lightness rule of thumb: in light mode foreground swatches sit around L=0.5–0.7. In dark mode the same hue wants L=0.7–0.85 to keep contrast on a dark surface. Hue + chroma stay constant; only L moves. This is what shadcn's pairs already do.
